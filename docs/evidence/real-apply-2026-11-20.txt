== FINDING 1: ping failed although TCP 8080 worked ==
Cause: the workload network ACL allowed inbound ICMP echo request (type 8) but nothing allowed the echo
REPLY (type 0). The ACL is stateless and the TCP/UDP return rules do not cover ICMP. The analyzer path is
TCP 8080, so it could not show this.
Fix: aws_network_acl_rule.in_icmp_reply_from_allowed (commit 37a347c).
Applied live (2 rules added, targeted apply). Re-check at 10:55Z: ping 3 sent, 3 received, 0% loss.

== FINDING 2: spoke-to-spoke hairpin through the hub NAT gateway ==
With no route to the other spoke, a packet followed the spoke's default route to the hub attachment. The hub
attachment subnet's default route goes to the NAT gateway. The NAT gateway sits in the public subnet, whose route
table sends 10.0.0.0/8 to the Transit Gateway (needed for return traffic of internet flows). The NAT gateway
forwarded the packet to the Transit Gateway, the hub table had learned both spokes, and the other spoke answered.
The earlier README and notes said such a packet "goes nowhere". That was written before any real test and was wrong.
Fix: a static blackhole route for the private supernet (10.0.0.0/8) in each spoke Transit Gateway route table
(aws_ec2_transit_gateway_route.spoke_private_blackhole, commit 34978b7). Longest-prefix match keeps every
propagated /16 (the hub, and an allowed spoke) working, while a disallowed spoke range now matches the blackhole.
Mocked tests: 8 passed, 0 failed (2 new). terraform fmt -check: passed.
